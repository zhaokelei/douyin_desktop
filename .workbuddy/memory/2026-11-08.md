## 修复：中文输入法下 X/Z 变组字（同日再增量）

**现象**：中文输入法（微软拼音）下按 X/Z 不触发快捷键，而是弹出候选框、显示输入信息。

**根因**：`Win32Window::SetChildContent()` 把键盘焦点给了 **Flutter view 子 HWND**，
而原 `DisableIme()` 只对**顶层 HWND** 调 `ImmAssociateContext(hwnd, nullptr)`；
那句 `ImmAssociateContextEx(hwnd, nullptr, 0)` 的 flags=0 是空操作。IME 上下文仍挂在
真正接收按键的子窗口上，按键先被输入法吃掉变成组字，Dart 收不到 `keyX`。

**改动**
- `windows/runner/flutter_window.cpp/.h`
  - `saved_ime_context_`（单个 HIMC）改为 `std::unordered_map<HWND, HIMC> saved_ime_contexts_`。
  - `DisableIme()` 先摘顶层，再 `EnumChildWindows` + `DetachImeChild` 递归摘掉所有子 HWND
    （含 Flutter view），并保存每个 HWND 的原 HIMC；每次 disable 都重跑（防第三方 IME 重挂）。
  - `InstallViewHook()`：`SetWindowLongPtrW(GWLP_WNDPROC)` 子类化 view HWND，
    用 `SetPropW` 把 `this` 挂到窗口属性上（静态 WndProc 里取回）。
  - `HandleViewMessage()`：IME 关闭态下吞掉 `WM_IME_SETCONTEXT/STARTCOMPOSITION/COMPOSITION/
    ENDCOMPOSITION/NOTIFY/CHAR` 并顺手再摘一次上下文；`WM_KEYDOWN` 收到 `VK_PROCESSKEY(0xE5)`
    时用 `MapVirtualKeyW(扫描码, MAPVK_VSC_TO_VK_EX)` 还原真实 VK 再交引擎。
  - `RestoreIme()`：先复位 `ime_disabled_`（否则重挂时的 IME 消息又被吞），再逐个
    `ImmAssociateContext` 还回去；焦点窗口没有上下文时 `ImmAssociateContextEx(..., IACE_DEFAULT)`。
  - `OnDestroy()` 先 `RemoveViewHook()` 再 `RestoreIme()`。
- `lib/core/ime_guard.dart`：新增 `resync()` + `_forceResync`，即使期望状态没变也强制下发一次。
- `lib/app.dart`：`WidgetsBindingObserver` 监听 `AppLifecycleState.resumed` → `ImeGuard.resync()`，
  应对切回前台/窗口重新激活后 IME 被系统重挂。
- `lib/features/player/player_page.dart`：新增 `_keyMatches(event, logical, physical)`，
  所有快捷键同时比对 `logicalKey` 与 `physicalKey`（IME 改写逻辑键时靠扫描码兜底）。

**踩坑**：第一版在 `RestoreIme()` 末尾加了
`SendMessageW(focused, WM_IME_SETCONTEXT, TRUE, ISC_SHOWUI... )` 想恢复输入法面板，
但 `ISC_SHOWUIALLGUIDELINE` 这个常量在 imm.h 里根本不存在（正确的是 `ISC_SHOWUIGUIDELINE`），
导致 C2065 + C2660 编译失败。该调用本来也多余——还回 HIMC 后系统自动恢复 IME UI，已删除。

必须 `$code=$LASTEXITCODE` 紧跟构建调用，并额外 grep 日志里的 `error C` / `Build process failed`。

## 03:10–03:50 内存缓存 + 设置页 + 硬解失败自动降级

**需求**：① 视频缓存进内存而不是硬盘，占用到 1GB 自动删「看过的」并释放内存，可开关；
② 首页加设置界面，可切硬解/软解、缓存方式等；③ 硬解失败时自动切 CPU 软解，不要只弹错误。

**新增文件**
- `lib/core/app_settings.dart`：`AppSettings` 单例（ChangeNotifier + SharedPreferences）。
  `DecodeMode{auto,software}`、`CacheMode{memory,disk,off}`、`memoryLimitMB`(默认 1024)、`qualityPref`。
- `lib/data/memory_video_cache.dart`：`MemoryVideoCache` 单例。
  127.0.0.1 随机端口起只读 HTTP 服务，把内存里的整条视频按 `Range` 切片返回；
  mpv 因此拿到一个"可 seek 的普通视频源"。条目纯内存，进程退出即释放，磁盘零写入。
  超限淘汰顺序：**先 played=true（看过的）→ 再 lastUsed 最旧**，`pinned`（正在播放）永不淘汰。
- `lib/core/memory_trim.dart`：`MemoryTrim.trim()`，Windows `psapi!EmptyWorkingSet`、
  Linux `malloc_trim(0)`，淘汰后调用，让任务管理器里的占用真的降下来（200ms 节流）。
- `lib/features/settings/settings_page.dart`：解码方式 / 缓存方式 / 内存上限 / 默认清晰度 /
  运行状态（进程内存、缓存占用、命中数）/ 立即清理内存。
- `tool/mem_cache_check.dart`：`dart run tool/mem_cache_check.dart`，
  纯 Dart 自测回环 HTTP + Range + 淘汰 + pin + clear，**19 项全通过**。

**改动**
- 首页 header 加齿轮按钮；`main.dart` 启动时 `await AppSettings.instance.load()`。
- `player_page`：`_cacheMode` 驱动三条链路；内存模式走 `urlFor/ensure`，
  打开前用 `_applyStreamSeekable(allowRange: memUrl != null)` 把 `stream-lavf-o`
  切成 `seekable=1`（在线抖音必须 `seekable=0`，否则 404）。
  `_seekTo` / `_seekViaCache` 增加内存分支，拖动时未命中就后台下完再补跳。

**硬解失败自动降级的真正修法（关键）**
本机实测 mpv 报：
`Failed to allocate AVHWDeviceContext.` → `AVHWFramesContext: Could not create the surfaces`
→ `h264: Failed setup for format dxva2_vld: hwaccel initialisation returned error.`
→ `Cannot load nvcuda.dll`，随后**自己**用软解把画面放出来了。
旧代码把这些当成普通错误 → 弹红色浮层，用户看到的就是"硬解失败还报错、没自动软解"。
现在两级兜底：
1. `_isHardwareRelated()` 识别上述文本（新增 avhwdevicecontext / avhwframescontext /
   hwaccel / dxva2 / nvcuda 等标记），这类错误**不再弹浮层**；
2. `_handleHardwareErrorEvent()` 等 600ms 看 `hwdec-current` 与 `position`：

## 2026-11-08 04:2x 移除内存缓存 + 预缓存改「秒命中」+ 缓存上限可配（FIFO 淘汰）

**需求变更**：用户放弃内存缓存（不再需要的复杂度），要求
① 优化预缓存做到秒命中 ② 设置里可改缓存大小上限 ③ 超上限删最早缓存的视频、循环往复。

**删除**
- `lib/data/memory_video_cache.dart`（回环 HTTP 服务整块删掉）、`tool/mem_cache_check.dart`。
- `CacheMode.memory` 与 `memoryLimitMB` 全部移除；旧持久化值 `'memory'` 在
  `AppSettings._parseCache` 里迁移成 `disk`，老用户不会掉进「无缓存」。

**磁盘缓存重写（lib/data/video_cache.dart）**
- **内存索引**：启动扫一次目录建 `Map<key,_Entry(path,bytes,savedAt,seq)>`，
  `lookup()` 变成**纯内存查表**（实测 40~60µs，零磁盘 IO）——"秒命中"的第一环。
  索引未建好时用一次 `existsSync` 兜底，避免假未命中。
- **全局单例** `VideoCache.shared`：进出播放页不重建索引，已下条目跨页复用；
  首页 `home_shell.initState` 就 `init()` 预热索引，进播放页时已 ready。
- **预取策略改为串行（concurrency=1）+ 不限速（rateKbps=0）**。
  原因：实测 720P 单条 27~85MB、并发 3 会把带宽摊薄成每条 2.5MB/s，
  谁都下不完；串行让 `index+1` 独占带宽，小视频 0.4~1.5s、40MB 约 5.5s 就绪。
  `index+1` 第一条、然后 +2..+4，**当前条排最后**（它已在线在播，排前面会占掉
  一整个时间片把下一条挤晚；拖动时走 urgent 插队，不受并发限制）。
- **保留窗口**放到 `index-2 .. index+4`：来回翻几条时刚下一半的任务不被取消重下。
- **淘汰改 FIFO**（用户明确要求"清除最早之前缓存的"）：按 `savedAt`（写入完成时间）
  升序删，`lookup` **不再刷新 mtime**——否则最早的条目会被顶到队尾永远删不掉。
  正在播放的文件（`markActive`）跳过；全是播放中的就停止（不会死循环）。
- `setMaxBytes()` 运行中可改，设置页改完立刻按新上限清一次。
- **新增 Content-Length 预检**：单条 > 总上限就不下（实测 73MB 那条在上限 60MB 时
  刚下完就被删，纯浪费流量）。日志「跳过 …：单条 xx 超过缓存上限」。
- `clear()` 保留正在播放那条（否则画面会断）。

**设置页（settings_page.dart）**
- 缓存区只剩「缓存在磁盘（推荐）」「不使用缓存（直连播放）」；
  上限档位 512MB / 1GB / 2GB / 4GB / 8GB（默认 2GB，键 `douyin_cache_limit_mb`）；
  占用条 + 条数同步读索引（不再遍历目录）、「清空缓存」、显示缓存目录路径。
- 运行状态：磁盘缓存 used/limit · 条数、命中/未命中/失败。

**验证**
- `flutter analyze lib` 0 error（19 条既有 info/warning，与改动前持平）。
- `dart run tool/disk_cache_check.dart`：本地 HttpServer 模拟 CDN（3MB / 1.6MB/s），
  **全部通过**——6 次切换 6 次命中（查询 40~60µs）；上限 3.5 条时 f0 被删、f4 保留；
  播放中的 k0 不被删；重启后索引条数/字节与目录完全一致。
- 离屏实机（串行预取、8 秒切一条、上限 2GB）：首条在线，之后
  **连续 4 次「命中本地缓存 → media 来源=磁盘缓存 seekable=true」**；
  单条 0.9MB/416ms、1.5MB/1034ms、3.6MB/435ms、41.6MB/5504ms、84.9MB/8866ms。
- 设置页截图确认：视频缓存两项 + 5 个上限按钮（2GB 选中）+ 占用条 + 清空缓存。
